# NP-HALL-PARAMETRIC-ENVELOPE prereg addendum A1: AIR family (A9.33 Q2, A9.34 M1)

`prereg_addendum_a1_air_family.json` is authoritative; this page restates it. Status **PREREGISTERED_NOT_RUN**, label
**PARAMETRIC / NOT_VALIDATED**. Registered 2026-10-08, before any AIR launch manifest and any AIR run. Lock:
`prereg_addendum_a1_air_family_lock.json`. v1 (prereg, case file, launch manifest, driver) is not edited.

## Supersedes addendum 01

The AIR family was first registered as `addendum_01_air_family.json` (commit a182f71; sha256 4988bdfd…, lock
`addendum_01_lock.json` efc96af4…). Under A9.34 the coordinator named this addition **addendum A1** (A2 and A3 are
reserved for other lanes). A1 supersedes addendum 01 before any AIR run.
- Every addendum 01 rule is carried over verbatim, except the changes listed in `changes_vs_addendum_01`.
- The addendum 01 files stay unchanged as history. No tool reads them any more.

## What it adds

A third family **AIR** (AIR_PRIMARY), built on the NP-HALL-CHEM-AIR reaction set
(`hallthruster_bridge/propellants_air/`, `air_nominal.toml`). XE and N2_PROXY are unchanged, and N2_PROXY still has no
role.

## Cases (9072)

Each AIR case combines:
- every frozen v1 N2_PROXY row (2268): geometry, B(z) registration, B_peak, V_d, mass flow, transport and numerics,
  copied unchanged;
- one of the four composition corners of NP-HALL-CHEM-AIR (CE-AIR);
- a feed split by mass fraction under the inlet rule NI-01 (500 K, 150 m/s × √(M_N2/M_s)).

The cases are generated by Rust and are byte-reproducible (`abep-air-cases generate | check`). Relative to addendum 01,
only the file header changes (addendum id, hashes, status); every case and its `case_sha256` are identical.

Labels: the v1 labels, plus:
- COMPOSITION_HULL_CORNERS_NOT_INTERIOR_BOUNDS;
- NEUTRAL_INLET_EQUAL_T_SCALED_FROM_V1_DEFAULT;
- CHEMISTRY_NOMINAL_ONLY.

## Launch gate: two paths

- **LP-COMPLETE** (addendum 01 unchanged). It opens only when the AIR set is COMPLETE_FOR_PARAMETRIC_ENVELOPE. Today it
  refuses: the set is INCOMPLETE_EVIDENCE.
- **LP-BOUNDED** (new). While the set is not admitted, the registered bounding variant set **BV-AIR-LL** (NP-HALL-CHEM-AIR
  addendum 03, label `BOUNDED_ONE_SIDED_LOWER_ELECTRON_IMPACT_LOSS_NOT_COMPLETE`) may run as labelled information. The
  gate requires all of the following, and refuses with MODEL_ERROR on any mismatch:
  - addendum 03 and its lock verify;
  - `AIR_PINNED.toml` is abep-air-0.7 with the addendum 03 sha256;
  - `rate_validity.toml` has the addendum 03 sha256;
  - `air_nominal.toml` is member BV-AIR-LL-NOM with its addendum 03 sha256;
  - `AirSet::load` passes.

  Only BV-AIR-LL-NOM runs here. Running BV-AIR-LL-ALT needs a new addendum with its own case file.

The manifest pins the case file, the driver, both Julia libraries, `AIR_PINNED.toml`, the configuration, the validity
file, every rate file and the chemistry mode (plus, for LP-BOUNDED, the set, member, label and addendum 03 hashes).
- Every record carries `chemistry_mode` and the BV fields.
- A record that disagrees with the manifest, or an envelope that mixes modes or labels, makes ingestion MODEL_ERROR.

## Run status

As v1, with one addition: OUT_OF_DOMAIN also covers DOM-AIR-01 (per-table f_out > 1e-12, or an unresolved table) and
DOM-AIR-02 (activity above 45 eV mean energy > 1e-12).

## Closure

- **Point tests.** T12 and T25 exactly as in v1.
- **Composition is not controllable.** A test closes on a hardware configuration (geometry, B shape) only if it passes at
  **every** composition corner. Any B_peak, V_d, ṁ and transport may be used at each corner. T12 and T25 must close on the
  same hardware.
- **Non-closure is never eligible for PHYSICALLY_NON_CLOSING.** The reasons are the surrogate B(z), corners that do not
  bound the interior, and a single chemistry configuration. A non-closure is recorded as HALL_NON_CLOSING_UNDER_AIR_ENVELOPE,
  and the classification stays NOT_DETERMINABLE.
- **Bounded variant (LP-BOUNDED).** The same tests are reported as labelled information only:
  BOUNDED_INFORMATION_CLOSES_AT_ALL_CORNERS or BOUNDED_INFORMATION_NO_CLOSURE_FOUND.
  - The constraint status stays NOT_DETERMINABLE_IN_ENVELOPE with blocker AIR_CHEMISTRY_BOUNDED_NOT_COMPLETE.
  - It is never a closure (SELECT) and never a non-closure.
  - It is never a bound on a Hall observable: addendum 03 D-3 claims no direction.
- **Excluded states.** The SB-He states (14) and SB-Ar states (6) stay NOT_EVALUATED until their bounds are resolved.
- **Evidence conditions added to C3:**
  - EC-COMP: delivered composition registered, inside the hull, and closing;
  - EC-CHEM: closure under the chemistry variants, and the version-of-record status;
  - EC-INLET: the registered feed state replaces NI-01.
- **Layer (b).** Unchanged: NOT_EVALUATED (credible set EMPTY).

## Execution and cost

- AIR is its own shard set and frozen raw file. Chemistry modes are never mixed. The driver is
  `driver/h1_envelope_air_driver.jl`, and staging by composition corner is allowed.
- There are 9072 runs, with 34 reactions and 9 species each. The extrapolated cost is ≥ 300 CPU-h.
- **OQ-HPE-AIR-01:** accept the full grid, stage it by corner, or reduce it in a new addendum?
- **OQ-HPE-AIR-02:** treat composition as uncontrolled (drafted), or as a gas-path design choice?
- The Rust ingestion and classification of AIR records are implemented when the gate first opens, following this addendum
  literally.
